# DAY 8 MVP 통합 검증

## 목적과 변경 범위

DAY 7까지의 기능을 실제 웹·API 흐름으로 묶어 회귀를 검증한다. 기존 기능별 테스트는 유지하고 tests/e2e/mvp-integration.spec.ts에 교차 화면·요청 수명 관련 시나리오를 추가한다. API 계약과 제품 구현은 검증에서 오류가 확인되는 경우에만 변경한다.

## 추가 시나리오

| 상황                | 기대 결과                                     | 검증 방식                                                             |
| ------------------- | --------------------------------------------- | --------------------------------------------------------------------- |
| 모바일 전체 흐름    | 검색·상세·차트·관심종목 영속화·삭제·목록 복귀 | 375px Chromium, 실제 REST와 Mock WebSocket, 브라우저 런타임 예외 수집 |
| 검색 응답 순서 역전 | 이전 검색 응답이 최신 종목을 덮어쓰지 않음    | 첫 검색 응답을 보류하고 다음 검색 완료 후 해제                        |
| 관심종목 API 장애   | 코드 유지, 재시도 후 종목명 복구              | 목록 요청 1회 실패 주입, 기존 localStorage 사용                       |
| 재연결 중 화면 이탈 | 목록에 돌아온 뒤 연결이 추가 생성되지 않음    | WebSocket 1012 종료 주입, 화면 이탈 후 가상 시계 20초 진행            |

네트워크 경계의 오류와 타이머를 제어해 실제 대기나 임의의 sleep에 의존하지 않는다. 정상 사용자 흐름은 실제 서버를 사용한다. 검색 응답 지연 테스트는 요청 시작을 확인한 뒤 다음 입력을 보내 의도한 순서 역전을 만든다.

## 실행

Node.js 24.x에서 README의 전체 품질 검사를 실행한다. E2E 전에 npm run build가 필요하며 테스트가 관리할 3000·4000 포트를 비운다. 현재 환경에서 이미 설치한 브라우저를 사용할 때만 PLAYWRIGHT_BROWSERS_PATH를 .tools/browsers로 설정한다. CI는 기존 워크플로가 Chromium을 설치하므로 이 로컬 경로가 필요하지 않다.

## 한계와 다음 작업

- Chromium에서 모바일 크기를 검사한다. Safari·Firefox 및 실제 모바일 기기 검증은 후속 범위다.
- WebSocket은 테스트용 합성 시세다. 거래소 시세·거래일·실제 네트워크 운영 환경을 검증하지 않는다.
- 가상 스크롤이나 렌더링 최적화 전에는 대표 데이터 규모와 측정 방법을 정하고 기준 성능을 기록한다. 현재 30개 종목만으로 성능 개선을 주장하지 않는다.
- 포트폴리오, 로그인, PostgreSQL 및 실제 데이터 연동은 기존 후속 범위를 유지한다.

## 로컬 검증 결과 — 2026-11-19

Windows, Node.js 24.22.1에서 format:check, lint, typecheck, test, build, test:e2e를 모두 통과했다. Vitest는 3개 파일 34개 테스트, Playwright Chromium은 23개 테스트(기존 19개와 신규 4개)를 통과했다. 신규 모바일 흐름에서는 pageerror가 없었다. 이번 검증에서 제품 코드 수정이 필요한 오류는 재현되지 않아 테스트와 문서만 변경했다.

Vitest에는 기존 CommonJS 설정의 향후 Vite native config loader 관련 안내가 출력되었다. 검사 실패는 아니며 이번 범위에서 설정을 변경하지 않았다. 원격 CI와 Codex 리뷰 상태는 PR에서 별도로 확인한다.
